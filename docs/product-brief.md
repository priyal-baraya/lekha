# Product brief

## The user

The owner or manager of a small independent bookstore. They know their shop and their readers well, but track stock and sales in spreadsheets or paper records. They are not data specialists and have limited time.

## The problem

With manual records it is hard to answer questions such as:

- Which books sell the most?
- Which genres bring in the most revenue?
- Which books are running low on stock?
- Which books have not sold recently, and may be taking shelf space without earning?
- Which genres or authors might deserve a featured display?
- What should be looked into before the next restocking order?
- How are sales and revenue changing over time?

## What Lekha does

Lekha turns the store's records into clear, checkable information that supports these decisions. It shows patterns; it does not claim to prove why they happened. Any suggestion it makes is labelled as a suggestion based on recorded data, and Lekha says so when there is not enough data to conclude anything.

## Core features (minimum viable product)

| Feature | Purpose | Planned phase |
|---|---|---|
| Book catalogue | View, search, filter, add and edit books | 3 |
| Inventory | Current stock, books at or below reorder level, stock corrections | 3 |
| Sales recording | Record a sale with several books, update stock safely in one step | 4 |
| Insights dashboard | Revenue, copies sold, transactions, best sellers, revenue by genre, trends | 5 |
| Actionable insights | Plain-language suggestions with their evidence and limits | 5 |

Possible later addition: a reading-event planner, only once the core is reliable.

## Navigation

Practical labels for the main sections: **Overview, Books, Sales, Inventory, Insights**. Literary language ("The daily read", "The bookshelf", "Shelf check") is kept for section introductions, never for the navigation itself.

## Goals for the project itself

This is a portfolio project. It should demonstrate relational data modelling, SQL, Python, data validation, analysis and visualisation, interactive application development and thoughtful visual design, and every part of it should be explainable in an interview.

## Out of scope for now

- AI or machine learning features
- Real store data or real personal data
- Accounts, logins or multi-store support
- A separate web frontend (React or similar)
